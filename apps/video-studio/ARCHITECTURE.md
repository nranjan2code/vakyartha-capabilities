# Video Studio architecture

`server.ts` owns canonical app state, source programme validation/import, library/history/playlists and exports. `creator.ts` owns project commands, snapshot acceptance, edit history/checkpoints, independent cuts and declarative editor views. `composition.ts` validates bounded clip contracts; `surface.json` is generated from the empty retained view. The package has no dependencies or raw network access.

One project record owns working programme, reviewed snapshot, optional scene proposal, parent reference and bounded history. A programme contains canonical scenes plus an optional timed composition. Clip instances retain ids, tracks, source references/in points, placement/duration, framing/focal point and sound parameters. Media owns bytes. Source apps own their records; only declared read-only MCP exports are read explicitly. The creator app retains imported programme snapshots, with visuals and speech from the same scene records.

Field/action dependencies: narration/title fields update the selected working record; clip fields and timeline commands update composition; scene operations update canonical scenes and their clip links; source append extends the selected project; accept replaces only that project's reviewed snapshot. Library queues read reviewed snapshots; editor preview reads working content. Watch progress, saved queues and playlists refer to project ids. Rendering makes no provider/source/voice call.

Projection supplies public workspace regions, icon buttons, stage and media-track controls. The host supplies the asset picker/importer, shared Media resolution, measured speech preparation and one composition transport. Storyboard selection saves a scene and its playhead position. The stage reads the same position, and local scrubbing previews retained content; playback clocks never belong to package timers. The same transport supplies editor preview, header Listen and Watch.

`get_creator_context` returns the current revision and selected scene/clip context. `propose_video` saves an unreviewed project; `propose_edit` saves an unreviewed selected-scene proposal. Both require host-checked expectedRevision. Acceptance is personal. The app preserves unavailable source/media and unreadable-record outcomes instead of inventing content.
