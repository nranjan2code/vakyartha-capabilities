# News Desk architecture

## Files

- `app.json`: manifest; brokered network with the single `web__fetch_page` tool; no database; an opt-in 15-minute `refresh` trigger; exports the read-only tools `get_latest_articles`, `get_bulletin` and `get_story_coverage`, feed `news_feed` and skill `news-desk-reader`.
- `server.ts`: `normalize`, `feed`, `opmlFeeds`, `refresh`, `handleAction`, `handleQuery`, and `view` with `topSurface`, `sectionsSurface`, `storySurface`, `followingSurface`, `savedSurface`, `sourcesSurface`; `surfaceFile()` for `surface.json`; manifest `voice.listen.selector` exposes canonical channel choices to the host header; shared `sectionLinks`/`sectionChips` and compact `storyCard`/`storyNodes` compose the same public Projection components; `channels`, `channelStories` and bounded reading signals derive personal radio selections from the same state.
- `rank.ts`: `terms`, `similar`, `group` (average-link story grouping with a singleton second pass), `matches` (topics), `discoverTopics` (trending topics across tags and headlines), `rank` (scored stories with reasons) and `diverse` (per-publisher cap). Pure.
- `bulletin.ts`: `speakable`, `lead`, `programme` (the bulletin as host programme parts: delivery, cues, breaks, and each story's own heading, image, publisher, time and link), `bulletin` (those parts as one script, for tools) and `storyReport`. Pure; fixed connecting phrases, publisher text only.
- `feed.ts`: `sourceBody` (the tool's original response), `parseFeed` (RSS, Atom, JSON Feed with media, enclosure and inline images, preferring the largest declared original over a thumbnail; authors and tags), `canonical`, `plain`.
- `surface.json`: `view({})`, generated by `node scripts/app-surfaces.ts`.

## Flow

```text
field edit → handleAction(bindPath) → filters, drafts, topic draft, OPML, image setting → view
Refresh / trigger → up to 15 active feeds, stalest first: web__fetch_page → sourceBody → parseFeed
  → merge by canonical URL (first-seen time kept) → health, receipts, problem → view
refresh → parseFeed (RSS/Atom/JSON Feed/news sitemap) → merge by URL → prune (removed feeds, age window, per-feed cap, overall bound; saved kept)
view(state, now) → rank(articles, follows, preferences, tuning, seen) → stories with score parts → 7 updates (nodes + whole data)
registry → lint, apply on the previous snapshot, commit state + surfaces atomically
```

## Data

State as in AGENTS.md. Surface data is derived per surface: `/lead`, `/forYou`, `/digest`, `/more`, `/spoken/bulletin` (programme); `/filters`, `/stories`; `/lead`, `/stats`, `/timeline`, `/articles`, `/related`; `/topics`, `/suggestions`; `/saved`; `/stats`, `/byCategory`, `/byDay`, `/byFeed`, `/categories`, `/feeds`, `/health`, `/receipts`, `/rotation`; `/tuning`, `/sections`, `/mutes`, `/rule`, `/preview`, `/learned`, `/keepLine` (Preferences). `tuning` in state holds section levels, muted words, weights, half-life, per-publisher limit, learning switch and retention.

## Boundaries

Each command runs in its app’s dedicated sandbox instance with a 30 s deadline with at most 16 governed tool calls; feeds are reached only through the governed tool. Responses over 240,000 characters, DTDs, entity declarations and malformed nesting are rejected. Feeds are read four at a time within the time budget and merged in rotation order. Images are URLs only; the app never downloads them. After a refresh the host saves the images its views show and lists their hosts in Access (Vakyartha ADR-079), so reading never waits on publishers. Headline word splitting is cached in the instance, so ranking and topic discovery stay fast (about 30 ms for 450 articles); a filter change returns only Sections. Limits as in README.md.

## Reading layout

Top stories uses four lead cards with public `imageLayout: "background"` (three-line headlines over the publisher image, a scrim for legibility) above a 2:1 headline/section split, reflowing in the surface container. More headlines (six per page), For you (six) and the section rail (three) retain complete derived collections. Sections derives one wrapping filter row from canonical `/filters`: Section with counts, Published, Publisher and Order use public `select.presentation: "dropdown"`; any non-default filter or empty result exposes Reset. Changing Section keeps the other filters. The heading no longer repeats the selected section. Sections shows four background-image leads and all remaining matching stories (12 per page), without the former 180-story truncation. Other story, bookmark and report cards use public `imageLayout: "thumbnail"` and `titleLines: 2`; two-column leads and three-column reading grids keep rows compact. Full canonical titles remain accessible and in tooltips/coverage. Missing images consume no placeholder area. Preview excerpts and secondary publisher headlines move into Full coverage, whose image is bounded to the small measure beside the source excerpt, counts and actions. Ranking reasons remain visible captions. Following uses topic choices and a twelve-story local page; Saved and related stories retain compact illustrated previews. Sources keeps its five operational panels with shorter feed summaries and full failures in Health. Routine rotation is caption text; actual failures retain the warning. All fields autosave through the same host boundary.

Buttons that only change view (back to Top stories, Review feeds, preferences) use the host's `view.open`, so they never run the app; `open_section` and `open_story` also set the section filter or story, so they stay app actions. No new persistence, renderer, CSS override or execution authority is introduced. Opening an article hidden by a disabled feed derives its coverage from that retained article so bookmarks remain useful. `scripts/news-desk-check.ts` exercises these layouts and actions through the actual app host, supervised sandbox and WebKit, with isolated state and optional replay of a retained publisher snapshot.

The header channel selector declares only a bind path, options path and accessible label on the existing listening surface. The host serializes that field change through the same app action queue, refreshing canonical surfaces and the header from the returned state; it creates no independent preference store. Selection is available from every view, before the radio button. No model call or playback starts from selection alone.

## Programme (Listen and Watch)

`programme(top, all, topics, clock, channel, images)` in `bulletin.ts` builds `/spoken/bulletin` on the top surface from the same ranked stories as the views. Order: opening (intro cue) → top five headlines (short parts) → up to twelve stories (sting on the first; three per section in a general bulletin; a second publisher's line on the first three) → up to three followed topics → every other section, three stories each (or fourteen more channel stories) → closing (outro cue). A `used` set keeps every story to one part, so length follows the feeds (about 34 parts and six and a half minutes on a typical day). Each part carries the story's title, its largest original image (`picture()`: the lead's, else another publisher's), publisher, time and link; `images: false` drops pictures. `bulletin()` joins the same parts as text for `get_bulletin`, which also returns `programme` for other apps.

Breaking stories (`isBreaking`: fresh by both first-seen and published time, and two or more publishers or a followed topic) lead the main stories, at most two. Every story the programme does not read goes to `ticker` (60, ranking order, `fresh` marked). The manifest's `voice.listen.live: 4` observes newer committed programmes during playback; Background operation owns source-refresh timing (see `docs/features/PROGRAMMES.md#live-shows`).

Change the shape here only; playback, music, speech shaping and the stage are the host's (see `docs/features/PROGRAMMES.md`). After a change run `node --test test/reference-apps.test.ts` and `node scripts/news-desk-check.ts`, and measure parts and minutes on real state.

## Hosted operation

The shared host supplies Background operation in this app and Operation Center; package views must not duplicate it or own timers. Start & keep running persists the choice and runs the declared startup-refresh handler now and whenever Vakyartha launches. Refresh remains a manual action; automatic timing uses the declared cron interval, a chosen host timer, or Manual only. Stopping background operation leaves manual actions and saved data available. Startup also runs in Manual only mode.

The host owns scheduling, serialized commits, bounded recovery and run receipts. A failed computation with no external calls receives up to three delayed retries; uncertain external effects block replay for exact-run review. Tools require this app’s explicit mode/tool/destination access; integration Off remains a ceiling, and execution needs an awake computer and running Vakyartha. Reviewed package updates stop background operation for renewed review. Playback observes saved programmes and never starts another refresh loop.

## Shared Access and package review

This package declares 1 integration tool. Its action requirements are listed in entitlements.toolActions; review tools and destinations in Access, with separate foreground/background choices. Source and domain preferences do not grant access. Keep saved records and source freshness separate from permission readiness.

The Vakyartha host owns the Access panel and permission reasons; Rust is the sole desktop grant writer. Do not add app permission dialogs/stores, permission-error regexes or global-Allow shortcuts. Skills and manifests confer no authority.

Review complete package source/fingerprints and the access delta before updating. Preserve domain data, stop Background and review access for the changed package; do not blindly update packages or edited/disabled/removed skills. Ask currently blocks for in-panel review, not a waiting sandbox approval. Follow the root docs/features/APP-ACCESS.md contract, including shared stdio/native-audit limitations and independent source/outcome gates.

The manifest marks every declared tool with a plain-language purpose and optional/needed status. `renderApp(context)` is this package’s effect-free update projection: it reads retained copies and returns the same canonical views without source calls. The host discards renderer state/database mutations, refuses a failed rebuild and keeps the original package/data/views.


## Interaction and refresh cost

The shared Apps host retains its header and assistant dock across view changes and reconciles only changed canonical views after actions or background refresh. Local search and paging stay in the surface. Field handlers save normalized drafts without external reads. Return all views affected by a domain change, including spoken projections. Prefer a focused update for a draft with no other consumers and preserve saved computed values. Keep SQL and source calls for operations that need them. Each app retains its own contained worker across successful commands. Keep running controls hosted scheduling and restart eligibility. Durable state belongs in host checkpoints. Measure saved-data clicks, draft saves, source refresh and cold open separately before claiming a latency improvement.
