# Architecture

`app.json` declares the internal read tools, Node 26 sandbox, and the tool-free render entrypoint. `evidence.ts` validates actual tool results, source/tenant/subscription identity and capture times, derives an inventory comparison, and encodes CSV. `visuals.ts` derives regional counts, paged resource group membership and direct prerequisite graphs from the same retained evidence and plans. `plan.ts` validates landing zone drafts, evidence findings and migration workflow rules. `server.ts` owns canonical local plan state and derives the three Projection views. `surface.json` is generated from the empty state.

Load scopes and load capture are independent explicit reads. They use the existing app-integration bridge with action-specific preflight. Only the requested tenant and subscription's previous and current observations are retained in the Workbench. The Ops Desk remains the capture owner. Changing scope clears observations and the active editors. Saved plans are keyed by tenant and subscription. An unavailable source remains visible as unavailable and cannot participate in an inventory comparison.

Scope changes rebuild all views. A capture affects estate evidence and landing zone inventory counts. Showing or hiding the source controls rebuilds only Estate explorer and uses no tools. Loading a capture returns the explorer to the evidence-first view. Findings and handoff edits affect Landing zones. Wave, workload and assessment edits affect Migration waves. The app registry serializes actions and commits checkpoint changes only after successful validation and projection. Report exports and header listening derive from the same retained evidence and are delivered by the host. There is no service endpoint or background writer.
