# Azure Infrastructure Workbench

Use this development app for customer infrastructure investigation, landing zone reviews and migration planning. Publish Azure Operations Desk first and register the customer subscription there. In Workbench, use the shared Access shield to review the two local read-only tools, then use **Load customer subscriptions** and **Load latest capture**. The app reads one selected tenant and subscription. Once a capture is loaded, use Change subscription or reload to show the source controls again. It retains the latest two loaded captures for that scope and clears the working cache when you change scope.

- **Estate explorer** shows coverage, a regional resource chart, searchable inventory, a resource group map, a source timeline, and changes between two complete inventory captures. Select a group to browse its resources and inspect individual nodes. Map lines show group membership. An entity absent from a new capture may reflect a change in visibility. Resource grouping comes from the control-plane inventory. Application traffic and in-guest dependencies need separate telemetry.
- **Landing zones** shows review progress across eight design areas. Review the priority area shown at the top, or choose a design area to inspect. Record its status and evidence, then save the finding. Virtual network and log workspace counts describe visible inventory. For a platform or application deployment, save the change reference and validated inputs under **Pipeline handoff**. The reviewed data is available in Saved inputs as JSON and as CSV for the existing deployment pipeline.
- **Migration waves** accepts manual discovery records and tab-separated rows from a reviewed assessment. Paste up to 60 headerless rows per import in the order shown on the Import assessment tab. Read the stage distribution and the verification progress for each wave, inspect recorded prerequisites in the dependency graph, and advance stages as test, approval, rollback, and verification evidence becomes available. Import is atomic. Export the migration plan with scope, owners, gates, references, and outcomes.

Each tenant and subscription has its own saved review and migration plan. Retained captures show UTC observations and distinguish a completed empty source from an unavailable one. Dates, statistics and the optional spoken briefing describe the saved capture. Workbench stores records locally and has no scheduled or external operations. Engineers execute and verify infrastructure changes in their own Azure pipeline.
