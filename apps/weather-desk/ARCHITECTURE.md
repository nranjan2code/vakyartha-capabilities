# Weather Desk architecture

| File | Responsibility |
| --- | --- |
| app.json | Six read entitlements, six initial views, startup/hourly refresh, shared listening selector, immutable exports and reader skill |
| data.ts | Bounded source parsing, coordinates/timezone/date/unit/series validation, missingness, WMO words, sky/symbol/day-phase mapping and unit conversion |
| server.ts | Schema 1 normalization, explicit local actions, governed sequential reads, retained errors/receipts and immutable queries |
| views.ts | Pure independent view projections on Projection scenes, matching daylight records, daily CSV and factual programme |
| surface.json | Exact empty-state projection generated by surfaceFile() |
| README.md / AGENTS.md / SKILLS.md | Operations, invariants and selected procedural support |

UI action or explicit host startup/timer → serialized app owner → fresh supervised sandbox → declared integration tool mailbox → validated source snapshot → atomic state/surface/receipt commit. `context.state` alone owns source facts, saved places and user fields. The host owns canonical persistence, revisions, operation choices, timing, failure retry and uncertainty recovery. Source-read failures are stored independently by dataset; successful reads replace only that dataset. A thrown invocation or timeout publishes nothing. The 40-entry source ledger supplements the host's run receipts.

Each saved place has six optional latest snapshots, each with local source series, source grid/timezone, explicit units and UTC read time. Metric source facts never change for a display preference. Schema normalization revalidates persisted snapshots through the same source boundary, bounds places and collections, drops malformed snapshots and keeps independent errors. There are no legacy shims or alternate writers. Field drafts persist through the same app state; read-only query invocation normalizes locally without assigning state and the host discards query mutations.

Every view's root is a Projection `scene` whose sky and day phase come from the selected place's saved WMO code, `is_day` and the source's sunrise/sunset (45 minutes either side is dawn/dusk); a missing code shows a plain clear sky and no symbol. Today leads with a hero (symbol, temperature, feels-like, high/low, freshness), then a 24-hour scrolling strip, a 10-day `rangebar` list on one shared temperature scale with the current temperature as a marker, symbol-labelled detail tiles, and the temperature chart. Forecast repeats the strip and the full day list beside the exact tables; Air leads with the US AQI and its US EPA category gauge; each saved place is a `scene` tile with its own sky. These are standard Projection components any app can author; nothing is drawn by app code. UI/CSV/briefing derive from the same facts. Charts use complete finite series; exact tables retain nulls. Local search/sort/paging never invokes the backend. Up to 48 future weather source hours and 16 local days are bounded; air covers two source-local days. Planning matches contiguous daylight records only and stays disabled for failed/stale conditions. Specialist snapshots are explicitly fetched and retained separately from core refresh, so date-editor changes cannot relabel a previously saved range. Main weather display conversion is deterministic; specialist/source units remain explicit.

Five places × conditions/hourly, daily and optional air uses at most 15 sequential governed calls within the shared 16-call/30-second invocation contract. Startup and hourly cron invoke the same bounded refresh, only after explicit persistent Keep running. Manual refresh is independent. Host timing/retry/recovery governs this app in both the app header and Operation Center. No polling loop in package/view/Watch, localStorage timer, permanent process, raw HTTP/DNS, listener, external file grant, dependency or worker model capability is added. Rust keeps its existing supervision, authority, credential/egress and safe export roles.

Immutable internal MCP queries return saved state/programmes only, without advancing revisions or reading sources. The internal provider opens no network port. Shared `assistant.compose` prepares an editable in-app request; Send uses the normal chat/skills/MCP/approvals/FinOps pipeline. No mutating exports, content proposals, feeds, database or parallel retrieval system exists. Voice and file.save delegate to the existing host/native owners. Changes to domain rules belong here; generic catalog/projector/binding defects belong in Projection's owning repository; integration installation and authority stay with the existing lifecycle.

Verification covers exact source-shaped fixture values, units/timezones/nulls/truncation, cross-view consistency, date limits, bounded calls, real sandbox commits and query immutability, durable reopening, supported-surface lint, wide/narrow WebKit controls/paging/links and Watch without speech. Live weather and real native export/audio receipts remain separately identified evidence. Source builds never imply installed-app replacement or successful model authoring.

## Shared Access and package review

This package declares 6 integration tools. Its action requirements are listed in entitlements.toolActions; review tools and destinations in Access, with separate foreground/background choices. Core refresh uses forecast and optional air; search, history, marine and river reads are separate explicit capabilities. Denied specialist access must not disable ordinary local edits or be treated as a forecast failure.

The Vakyartha host owns the Access panel and permission reasons; Rust is the sole desktop grant writer. Do not add app permission dialogs/stores, permission-error regexes or global-Allow shortcuts. Skills and manifests confer no authority.

Review complete package source/fingerprints and the access delta before updating. Preserve domain data, stop Background and review access for the changed package; do not blindly update packages or edited/disabled/removed skills. Ask currently blocks for in-panel review, not a waiting sandbox approval. Follow the root docs/features/APP-ACCESS.md contract, including shared stdio/native-audit limitations and independent source/outcome gates.

The manifest marks every declared tool with a plain-language purpose and optional/needed status. `renderApp(context)` is this package’s effect-free update projection: it reads retained copies and returns the same canonical views without source calls. The host discards renderer state/database mutations, refuses a failed rebuild and keeps the original package/data/views.


## Interaction and refresh cost

The shared Apps host retains its header and assistant dock across view changes and reconciles only changed canonical views after actions or background refresh. Local search and paging stay in the surface. Field handlers save normalized drafts without external reads. Return all views affected by a domain change, including spoken projections. Prefer a focused update for a draft with no other consumers and preserve saved computed values. Keep SQL and source calls for operations that need them. Each app retains its own contained worker across successful commands. Keep running controls hosted scheduling and restart eligibility. Durable state belongs in host checkpoints. Measure saved-data clicks, draft saves, source refresh and cold open separately before claiming a latency improvement.

The packaged assistant skill uses checked domain steps for its declared tools and interpretation. Vakyartha supplies the shared presentation procedure over retained results; this skill does not author report layout. Text requests remain text, and proposal writes still require the existing permissions and personal review.
