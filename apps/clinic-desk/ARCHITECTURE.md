# Clinic Desk: architecture

## Files

| File | Role |
| --- | --- |
| `app.json` | Identity; `runtime.engine: "node26"`; airgap; no tools or database; header listen at `/spoken/brief` |
| `server.ts` | State, `normalize()`, `freeSlots()`, `handleAction()`, one builder per surface, `renderApp()` |
| `intel.ts` | No-show risk (naive Bayes in log-odds, smoothed) and the seven-day outlook, from resolved visits only |
| `show.ts` | The day as a programme for Listen and Watch (segments, figures, week chart, ticker) |
| `surface.json` | The empty-clinic views, generated by `node scripts/app-surfaces.ts` on a fixed clock and zone |

## Data flow

```text
action or field edit → normalize(state) → mutate records → view(state, touched surfaces)
```

Surfaces: **today** (Schedule), **book**, **patients**, **doctors**, **insights**, **setup**. `insights.ts` derives reports, attention prompts and patient facts from the records on each run. Each is derived whole from state; `touched` limits which are returned. Unreachable nodes are pruned (`reachable`), so a branch the state does not show leaves no orphan. Each view is one screen: a summary caption, one action bar, then `tabs`; lists and their open record share a `split`. Actions that move the person set `ui.go[screen] = {tab, n}`, published as `tabs.active` `"tab#n"`, so opening a day, booking, joining the waiting list, opening a patient or a doctor lands on the right tab even when asked twice. Calendars receive the weeks around the shown one because they page by themselves. Dependency map: draft fields touch `book`; the schedule date, doctor filter and Day list/Week/Month view touch `today`; new-patient fields and patient notes touch `patients`; walk-in, quick book, waiting-list and open-day actions focus Book or Schedule; booking clears the patient's waiting-list entry; status changes touch `today`, `book` and `patients`; doctor, leave and clinic edits touch every surface because slots and labels depend on them.

## Intelligence, programme and assistant

`todaySurface` builds one model per run (`riskModel`), scores waiting appointments, computes the outlook, and hands plain facts to `show.ts`, so the programme, the rows and the insight line agree. `handleQuery` serves the read-only exports; `prepare_booking` writes only `ui.draft`. The assistant panel is host-drawn (ADR-062) and gets the app's exports and nothing more.

## Boundaries

- **Empty charts.** Insights derives the visit-type pie only from nonempty visit counts; otherwise it emits a caption, with no synthetic slices.
- **Sandboxed like every app.** The registry runs this module in the shared sandbox worker pool with the same revision, checkpoint and receipt path as any app. Queries and renders never write. There is no tool call or database.
- **Time.** All dates are `YYYY-MM-DD` and times `HH:MM` on the clinic's clock. The only clock read is `context.now()`.
- **Host actions.** `file.save` (CSV) and the header listen are declared, never performed here.
- **Interaction.** The app keeps one retained instance; local paging and search keep long patient lists responsive. Wide and narrow WebKit checks cover the schedule (day list, week and month, and its tabs), booking, walk-in, patients (add, open) and setup, including four doctors switching without placeholder rows. Doctor choices are chips, not dropdowns, so there is no empty "Choose…" entry to mis-pick.

The packaged assistant skill uses checked domain steps for its declared tools and interpretation. Vakyartha supplies the shared presentation procedure over retained results; this skill does not author report layout. Text requests remain text, and proposal writes still require the existing permissions and personal review.
