# NSE Market Terminal architecture

## Files

- `app.json`: manifest; brokered network with 18 NSE read tools and News Desk's query tool; DuckDB storage; an opt-in five-minute `refreshMarket` trigger; exports `get_market_summary`, feed `market_feed` and skill `nse-market-analyst`.
- `server.ts`: state types, `normalize`, `symbols`, `paise`, `tracked`, governed `read` with receipts (including source timestamps on arithmetic validation failures and bounded row-drop diagnostics on aggregate reads), `refreshMarket`, `checkAlerts`, instrument research, index study, `handleAction`, `handleQuery`, `surfaceFile()`.
- `views.ts`: pure `view(state, analysis, now)` and the eight surfaces with `tabbed()` sub-views; `session`, `portfolio` (paise arithmetic), `marketBrief` (the spoken brief), `portfolioCsv` (derived exact-paise CSV) and formatting.
- `source.ts`: decoding and validation of every NSE tool's documented output (quotes, all index groups, history chunks, movers, breadth and VIX, bulk closes, search, 52-week, benchmark comparison, corporate actions, volume, most active, index movers, performance, history, valuation, comparison, index names). Arithmetic mismatches retain source time and diagnostic inputs without repairing the observation. NSE's own `{"error"}` sentences pass through.
- `show.ts`: `marketProgramme(state, analysis, now)`, the market show for Listen and Watch (badge, figures, line and bar charts, breaking parts, ticker); pure.
- `analytics.ts`: the `prices` table, transactional history replacement and the SQL analysis (returns, drawdown, 20/50-session averages, volatility).
- `surface.json`: `view({})`, generated by `node scripts/app-surfaces.ts`.

## Flow

```text
field edit (batched by host) → handleAction(bindPath) → save draft or filter → render
Refresh / trigger → all indices + movers + ≤12 live quotes (live) + mood + bulk closes (daily), each only when due and read together; the Refresh button forces the live ones → checkAlerts → recordIntraday (market hours, when something was read) → receipts with durations, problem → render
Open → research saved since the last publication for this window → a quote only if it can have moved → render (focus Instrument); otherwise as Analyse
Analyse → quote + history (latest month merged into a saved window that still covers it, else chunks; DuckDB transaction), always read; 52-week, vs benchmark (also by benchmark and window), actions, volume, each only when due; News Desk; read together → render (focus Instrument)
Refresh movers / Explore / Compare / Search / Add watch / Save holding → their reads → render
render → analyze(prices, symbol) → view(state, analysis) → 8 updates (nodes + whole data)
registry → lint, apply on the previous snapshot, commit state + database + surfaces atomically
```

## Data

State: `watchlist[]` (active list), `groups{name:symbols[]}`, `group`, `groupDraft`, `watchDraft`, `holdings[]` (`qty`, `cost` in paise), `holdingDraft`, `alerts[]`, `alertDraft`, `triggered[]`, `symbol`, `symbolDraft`, `months`, `benchmark`, `research{symbol}`, `historyFor{}`, `quotes{symbol}` (with `basis` live or close), `indices[]` (with group), `indexGroup`, `segment`, `movers`, `mood`, `active`, `period`, `indexMovers`, `searchDraft`, `results[]`, `indexNames[]`, `study`, `studyDraft`, `compareSet[]`, `compareMonths`, `comparison`, `receipts[]` (≤ 60, each with `ms`), `readAt{request}` (≤ 300 marks: `at`, source `day`, `slot`), `problem`, `checkedAt`. DuckDB: `prices(symbol, date, open, high, low, close, volume)`, primary key `(symbol, date)`.

Instrument passes one ordered history to its linked price, volume, returns and drawdown charts. The comparison and session drill-down run locally in the renderer. The marker list intersects retained corporate-action dates with the displayed sessions.

## Freshness

`fresh(mark, tier, now)` decides whether a saved value is current, from the India clock alone:

- `live`: in the session (weekdays 09:00–15:35) for one minute; outside it, when read after the latest weekday 15:35, so one read after the close keeps the final values.
- `daily`: when read after the latest weekday 18:30 and the source's own session day, if it names one, is not older than that day. A read is never repeated within 30 minutes, which bounds retries when a publication is late or the day is an exchange holiday.
- `fixed`: for seven days.

`read()` keys a mark by tool and exact arguments, writes it only on success, clears it on failure and removes other marks of the same `slot`. Stock history is not marked: Analyse always reads its latest month.

## Boundaries

Each command runs in its app’s dedicated sandbox instance with a 30 s deadline with at most 16 governed reads through the tool mailbox. The database is a bounded snapshot stored with the app record. Limits: 10 named watchlists with 30 symbols each, 50 holdings, 40 alerts, 80 history rows per chunk (EQ series only), 120 indices per group, 60 receipts.

## Shared host capabilities

The Portfolio uses the standard `file.save` action with a resolved `/export/csv` payload. The host handles the explicit click, safe filename and native Downloads receipt; the backend receives no filesystem grant. Per-app voice choice is a host preference and uses the existing Voice provider/transport. Both capabilities are documented for ordinary app authors; no bespoke app renderer or privileged tool exists. History uses standard record-bound charts with `xScale: "time"`.

## The market show (Listen and Watch)

`marketProgramme` builds `/spoken/brief` from the same state and analysis as the views. Opening (intro; badge from `session()`) → breaking (fresh alerts, big index moves in session) → headlines over the bed (Nifty 50 and Nifty Bank with figures and today's line, broader market bars, India VIX) → sting → breadth, sectors (bars, top and bottom six when many), gainers, losers, watchlist (bars, then line charts for its two biggest movers with readings), instrument analysis (daily closes with return, volatility, drawdown, 20/50-session averages), portfolio, earlier alerts → closing (outro, delay and not-advice note). Ticker: every non-sector index, the watchlist, then sectors, each with its change. Spoken text names companies (`company()` in `views.ts`, from `names.json`: NSE's equity list shortened as said, regenerated with `scripts/nse-names.ts`); headings show the name and ticker, figures and the ticker keep the symbol. Large sums are said rounded in lakh or crore. Parts are keyed by stable headings, so a live refresh updates their numbers and charts in place while the words already spoken stay.

`state.intraday` holds today's readings (`recordIntraday`, called by `refreshMarket` during market hours; one point per changed value; India-time day; 400 points per series). A line chart needs three readings and carries `base` = previous close, so its change matches the figures. The manifest's `voice.listen.live: 3` observes newer committed programmes during playback; Background operation owns source-refresh timing (`docs/features/PROGRAMMES.md#live-shows`).

Change the show only here; charts, figures, ticker, badge and playback are the host's. After a change run `node --test test/market-terminal.test.ts` and `node scripts/market-watch-check.ts` (WebKit at 1440 and 720 px, seeded session, no NSE or speech requests).

## 3.4 input, coverage and presentation

`draftText` preserves finite numeric input events (not arbitrary coercion) in the string draft owner. Save validates the count and cost, then records a failed quote read without dropping the holding. Portfolio coverage controls missing totals and chart emission. Standard public Projection measures/dropdowns/grids compose the narrower controls and metric strips; no framework renderer override is used.

`show.ts` requires same-day intraday recordings with an endpoint matching the current observation. The Live badge additionally requires a recent exchange timestamp during market hours. Segment source text carries saved timing/coverage; charts disclose their reference and fitted scale in the shared Watch renderer. Watch measures the lower third to reserve room for attribution and captions. The app host exposes persistent action errors and deduplicates identical connection messages.

`scripts/market-layout-check.ts --record <path>` copies only state/database into an isolated freshly published package, runs actual numeric field/save/error/correction actions and checks Instrument/Index geometry in WebKit. It never updates installed state or calls NSE/model/speech.

## Hosted operation

The shared host supplies Background operation in this app and Operation Center; package views must not duplicate it or own timers. Start & keep running persists the choice and runs the declared startup-refresh handler now and whenever Vakyartha launches. Refresh remains a manual action; automatic timing uses the declared cron interval, a chosen host timer, or Manual only. Stopping background operation leaves manual actions and saved data available. Startup also runs in Manual only mode.

The host owns scheduling, serialized commits, bounded recovery and run receipts. A failed computation with no external calls receives up to three delayed retries; uncertain external effects block replay for exact-run review. Tools require this app’s explicit mode/tool/destination access; integration Off remains a ceiling, and execution needs an awake computer and running Vakyartha. Reviewed package updates stop background operation for renewed review. Playback observes saved programmes and never starts another refresh loop.

## Shared Access and package review

This package declares 19 integration tools. Its action requirements are listed in entitlements.toolActions; review tools and destinations in Access, with separate foreground/background choices. Ordinary market refresh is separate from optional research and the News Desk query. A local cross-app read has its own app tool grant; it is not an external exchange connection.

The Vakyartha host owns the Access panel and permission reasons; Rust is the sole desktop grant writer. Do not add app permission dialogs/stores, permission-error regexes or global-Allow shortcuts. Skills and manifests confer no authority.

Review complete package source/fingerprints and the access delta before updating. Preserve domain data, stop Background and review access for the changed package; do not blindly update packages or edited/disabled/removed skills. Ask currently blocks for in-panel review, not a waiting sandbox approval. Follow the root docs/features/APP-ACCESS.md contract, including shared stdio/native-audit limitations and independent source/outcome gates.

The manifest marks every declared tool with a plain-language purpose and optional/needed status. `renderApp(context)` is this package’s effect-free update projection: it reads retained copies and returns the same canonical views without source calls. The host discards renderer state/database mutations, refuses a failed rebuild and keeps the original package/data/views.

Portfolio, alert, watchlist and index drafts and the movers period use the relevant view builder directly. Their projections have no DuckDB price-history dependency. Market refresh and package rendering still derive the complete set of views.


## Interaction and refresh cost

The shared Apps host retains its header and assistant dock across view changes and reconciles only changed canonical views after actions or background refresh. Local search and paging stay in the surface. Field handlers save normalized drafts without external reads. Return all views affected by a domain change, including spoken projections. Prefer a focused update for a draft with no other consumers and preserve saved computed values. Keep SQL and source calls for operations that need them. Each app retains its own contained worker across successful commands. Keep running controls hosted scheduling and restart eligibility. Durable state belongs in host checkpoints. Measure saved-data clicks, draft saves, source refresh and cold open separately before claiming a latency improvement. Independent reads start together (the host keeps four in flight), so a market refresh takes about its slowest read rather than their sum; Open of a symbol researched today makes no read (`savedForToday`), and the daily sources are kept for the India day.

## 3.4.7 criteria and accepted results

`moverSegment` maps documented source segment identifiers and displayed labels to the manifest's four criterion values. `readMovers` checks identity before commit. Overview's `show_movers` performs one governed read; `refresh_movers` retains the full four-read operation. Both rebuild every affected view and the canonical programme. Pure view titles use `movers.segment`; separate notes describe draft `segment`/`period`, accepted snapshot identity and the explicit action. Comparison output carries `from`/`to`; picker options include retained study/comparison selections. A partial Overview emits its secondary column only when breadth or portfolio data exists.

Dependency map: `segment` → Overview + Movers (full render retains Instrument/Watch); `period` → Movers only; `indexGroup` → local live-index rows; `studyDraft`, `compareSet`, `compareMonths` → Indices controls with accepted study/comparison unchanged; holding/alert/watch/search/list-name drafts → their one owning view. Source calls occur only on explicit actions and declared host refresh. Tests count calls, forbid unrelated SQL and verify actual contained commits/reopen.

## 3.4.8 transient owners

Search owns `searchDraft`, `searchQuery`, `searchMessage` and `results`. Normalization admits matches only with a known accepted query equal to the trimmed draft. An edit invalidates matches/messages; explicit `clear_search` clears all four fields. Search reads update Watchlist plus Sources only; local draft/reset work opens no history SQL and does not change market freshness/problem. Receipt projection uses the independent Sources builder. Unknown-query older matches are transient and discarded.

`clear_holding_draft` and `clear_alert_draft` return their one owning view without touching saved collections. `prepare_alert` returns/focuses Alerts only, preserving the threshold for the same symbol and clearing it for another. No timer or navigation-wide reset was added. Tests distinguish transient resets from durable records and preserve failed-validation correction.

Removing a holding also clears a draft for that symbol; drafts for other holdings remain intact.

## 3.4.9 direct movers selection

Overview and Movers share action buttons for the four stock-mover segments. Clicking a choice calls `show_movers` with its validated segment and reads that segment in the same action; no separate Show movers submission remains. Both chart projections and the programme rebuild from the accepted source result. Failed reads retain accurately labelled earlier observations and the existing failure message. Access rules are unchanged. The earlier 3.4.7/3.4.8 draft-and-submit guidance is superseded for these two movers selectors. Other multi-field forms retain their existing submission behavior.


The app exports one market assistant skill for tool selection and the meaning of returned values. It declares no rendering steps or presentation dependency; Vakyartha owns presentation for every domain.
