# Clinic Desk: architecture

## Files

| File | Role |
| --- | --- |
| `app.json` | Identity; `runtime.engine: "host"`; airgap; no tools or database; header listen at `/spoken/brief` |
| `server.ts` | State, `normalize()`, `freeSlots()`, `handleAction()`, one builder per surface, `renderApp()` |
| `intel.ts` | No-show risk (naive Bayes in log-odds, smoothed) and the seven-day outlook, from resolved visits only |
| `show.ts` | The day as a programme for Listen and Watch (segments, figures, week chart, ticker) |
| `surface.json` | The empty-clinic views, generated by `node scripts/app-surfaces.ts` on a fixed clock and zone |

## Data flow

```text
action or field edit → normalize(state) → mutate records → view(state, touched surfaces)
```

Surfaces: **today** (Schedule), **book**, **patients**, **doctors**, **insights**, **setup**. `insights.ts` derives reports, attention prompts and patient facts from the records on each run. Each is derived whole from state; `touched` limits which are returned. Unreachable nodes are pruned (`reachable`), so a branch the state does not show leaves no orphan. Dependency map: draft fields touch `book`; the schedule date, doctor filter and List/Week view touch `today`; new-patient fields and patient notes touch `patients`; walk-in, quick book, waiting-list and open-day actions focus Book or Schedule; booking clears the patient's waiting-list entry; status changes touch `today`, `book` and `patients`; doctor, leave and clinic edits touch every surface because slots and labels depend on them.

## Intelligence, programme and assistant

`todaySurface` builds one model per run (`riskModel`), scores waiting appointments, computes the outlook, and hands plain facts to `show.ts`, so the programme, the rows and the insight line agree. `handleQuery` serves the read-only exports; `prepare_booking` writes only `ui.draft`. The assistant panel is host-drawn (ADR-062) and gets the app's exports and nothing more.

## Boundaries

- **Host engine.** `sidecar/sandbox-pool/host-apps.ts` imports this module statically and runs it in the engine through the registry's `runBackend`, with the same revision, checkpoint and receipt path as sandboxed apps. Queries and renders never write. There is no tool call or database, and the registry refuses the host engine for any package that is not identical to the bundled one.
- **Time.** All dates are `YYYY-MM-DD` and times `HH:MM` on the clinic's clock. The only clock read is `context.now()`.
- **Host actions.** `file.save` (CSV) and the header listen are declared, never performed here.
- **Interaction.** The app keeps one retained instance; local paging and search keep long patient lists responsive. Wide and narrow WebKit checks cover the schedule (list and week), booking, walk-in, patients (add, open) and setup, including four doctors switching without placeholder rows. Doctor choices are chips, not dropdowns, so there is no empty "Choose…" entry to mis-pick.
